# Задание «Печать ценников»

Постоянное задание магазина (сервис `price_print`) со списком товаров, которым нужен новый ценник.
Миграция `018_price_tag_tasks.sql` добавляет тип «Печать ценников», если типа с сервисом `price_print`
ещё нет, и таблицу `price_tag_task_items` — позиции задания, по одной на товар.

## Как живёт задание

Задание не создаётся ни вручную, ни по расписанию: RMS ведёт его сам.

- У магазина одно постоянное задание. RMS создаёт его, когда товару впервые нужен ценник (при запросе
  `GET /tasks/current` с главной или при постановке товара из карточки), и никогда не закрывает.
- При каждом открытии в задание попадают товары, у которых появилась новая причина.
- Главная показывает задание, пока в нём есть ненапечатанные ценники или ценники, напечатанные сегодня.
  `GET /tasks/current` отдаёт у него `price_tags_pending` — число ценников к печати: больше нуля — задание
  активное, ноль — неактивное (всё напечатано сегодня). Назавтра неактивное задание с главной пропадает.
- Экран задания показывает ненапечатанные позиции и напечатанные сегодня.
- Первая отметка печати переводит задание в работу. Кнопки «Завершить» нет.
- `GET /tasks/types?store_id=…` не отдаёт этот тип, `POST /tasks/manual` для него отвечает 409.
  Сверка расписания такие задания не трогает.

## Откуда берутся позиции

Товару нужен новый ценник, если причина появилась позже последней печати его ценника в этом магазине
(в любом задании) и у товара есть обычная цена. Причины (`source`; при одном времени — по приоритету):

| source | Причина | Время причины | Ценник по умолчанию |
|---|---|---|---|
| `stopper_bad` | В задании «Стопперы» магазина товар отмечен «Не соответствует» | время отметки | акционный, если идёт акция |
| `promo_start` | Начался период позиции со стоппером | день «с» | акционный |
| `promo_end` | Период стоппера закончился накануне, другого действующего стоппера нет | день после «по» | стандартный |
| `revaluation` | Цена магазина изменилась сегодня в 1С: строка `today_price_changes` (обычная или акционная цена; таблицу каждый час перезаливает задание `today_price_changes_sync`) | время, когда изменение пришло в RMS (`arrived_at`), но не раньше начала дня | акционный, если идёт акция |
| `manual` | Добавлен в задании поиском или сканером либо из карточки товара | время добавления | акционный, если идёт акция |

Причины ищутся с первого задания «Печать ценников» магазина, но не дальше 60 дней назад. Поэтому после
установки задание начинается с изменений текущего дня, а не со всей истории цен.

`actual_at` — время последней причины позиции. Позиция напечатана, пока `printed_at >= actual_at`. У позиции видна последняя печать, сделанная до попадания
в задание (`last_printed_at <= actual_at`; при печати прежнее время сохраняется в `prev_printed_at`).
Новая причина у уже напечатанного товара сдвигает `actual_at`, и ценник нужно печатать снова; время прошлой
печати сохраняется. Повторное добавление вручную ещё не напечатанной позиции добавляет один ценник,
а напечатанной — снова ставит её в печать. Позиции с причиной не удаляются; ручную можно убрать, пока её не печатали.

1С не передаёт время изменения, поэтому RMS запоминает, когда строка `today_price_changes` пришла
(`arrived_at`, миграция `020_today_price_change_arrival.sql`): при перезаливке строка с той же ценой сохраняет
своё время, новая или изменившаяся получает время синхронизации. Изменение, пришедшее после печати в тот же
день, снова ставит товар в печать с новой ценой. Строка, пришедшая накануне, датируется началом дня — изменение
относится ко дню, в который пришло.

## Печать

Печать — в браузере магазина: ценник 60×47 мм по спецификации, 18 штук на лист A4 (3×6 вплотную, общая
линия реза), перед печатью предпросмотр листов. Единица измерения позиции (`unit`): `pc` — шт для штучного
товара, у весового — `kg` (1 кг, по умолчанию) или `100g` (цена на ценнике делится на 10). Тип ценника: `regular` — одна цена, `promo` — акционная цена
и перечёркнутая обычная, `card` — цена с картой «Икорный» и обычная как «цена без карты».

Цены на ценнике — цены магазина на сегодня. Если 1С прислала изменение на сегодня (`today_price_changes`),
ценник печатается с ним: строка без признака акции задаёт обычную цену, с признаком — акционную (0 — акции
нет), цена действует с сегодняшнего дня — изменение относится ко дню, в который пришло. Иначе обычная — последняя
запись типа цен магазина, акционная — последняя запись акционного типа цен, если она больше нуля. Период акции —
период стоппера или день перед следующей записью акционного типа. В задании у позиции видны статус «Напечатан» /
«Не напечатан», с какого дня актуальна цена и когда ценник товара печатали последний раз.

## API (с access-cookie)

| Метод | Назначение |
|---|---|
| `GET /tasks/{id}/price_tags` | Экран задания: магазин, статус, позиции с ценами (`pending`, `actual_at`, `printed_at`, `last_printed_at`) |
| `POST /tasks/{id}/price_tags` | `{"product_id":"…"}` — добавить товар вручную |
| `PUT /tasks/{id}/price_tags/{item}` | `{"tag_type":"regular"\|"promo"\|"card","quantity":1..99,"unit":"pc"\|"100g"\|"kg"}` — тип ценника, количество и единица (шт — только штучный товар, 100 г / 1 кг — только весовой; иначе 400) |
| `DELETE /tasks/{id}/price_tags/{item}` | Убрать ручную позицию, которую ещё не печатали (остальные — 409) |
| `PUT /tasks/{id}/price_tags/printed` | `{"ids":[…]}` — отметить напечатанными; автор — из токена; отдаёт `{"status":…}` |
| `GET /tasks/{id}/price_tags/products?q=…` | Поиск товара по названию, коду или штрих-коду (от 2 символов) |
| `GET /tasks/price_tags/product?store_id=…&product_id=…` | Для карточки товара: задание, позиция товара в нём, последняя печать ценника и стоппер товара сегодня (`stopper`: название и цвет) |
| `POST /tasks/price_tags/product` | `{"store_id":"…","product_id":"…"}` — поставить товар в задание из карточки (задание создаётся, если его ещё нет) |

Изменять можно только задание в статусе «Новое» или «Выполняется».
