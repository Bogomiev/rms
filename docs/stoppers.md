# Стопперы

Стоппер — ценник-наклейка на полку (Выгодно, ХИТ, Новинка и т. п.). Справочник
стопперов хранится в таблице `stoppers`: наименование до 24 символов (без учёта
регистра уникально) и цвет `#RRGGBB`. Миграция `012_stoppers.sql` создаёт справочник
со стопперами из регламента и таблицу позиций `stopper_positions`.

## Позиции

Позиция — товар из документа акции 1С (`doc_id` + `product_id`) или товар,
добавленный вручную (`doc_id` пустой, не больше одной ручной позиции на товар).

Акционные позиции берутся из снимка цен `GetPrices`: записи с ценой больше нуля
в акционных видах цен магазинов (`stores.price_type_promo`). Позиция начинается
с даты акционной цены и действует до дня перед следующей записью того же вида цены
и товара; если следующей записи нет хотя бы в одном виде цены — без срока.
В 1С на каждый акционный вид цен (регион) обычно свой документ, поэтому один товар
может быть в списке несколько раз; `stores` — число магазинов, на которые действует
документ.

Строка в `stopper_positions` появляется только после первого изменения: стоппер
и период («с»/«по») акционной позиции хранятся в ней и больше не зависят от 1С.
Удалить позицию нельзя — её закрывают датой «по». При удалении стоппера из
справочника позиции остаются без стоппера.

Цены в списке — по выбранным магазинам: текущая обычная цена (`price_type`,
время в `scheduler.timezone`) и цена документа в акционном виде цен магазина.

## Срок стоппера

У стоппера в справочнике может быть срок в днях (`stoppers.days`, миграция `019_stopper_days.sql`,
у «Новинки» — 28 дней). Когда такой стоппер ставят на позицию, дата «по» становится датой «с» + срок;
если позиция уже заканчивается раньше (конец акции в 1С или дата, выставленная вручную), остаётся более
ранняя дата. Пустой срок — открытый период, как раньше. Повторная установка того же стоппера и снятие
стоппера период не меняют; ручная позиция со стоппером со сроком сразу получает дату «по».
Срок — только значение по умолчанию: период потом можно изменить. Новый срок в справочнике действует
на следующие установки, уже выставленные даты не пересчитываются.

## Режим хранения

Отдельных режимов хранения в RMS нет. Используется признак товара из 1С `products.is_thermal_mode`
(`isThermalMode` в `GetGoods`): в API позиций и задания он отдаётся как `thermal_mode`. Позиции
группируются на «Терморежим» (холодильник или морозильный ларь) и «Без терморежима» (стеллаж).

## HTTP API

Все методы `/stoppers/…` — только администратор или пользователь с ролью `manager`
(миграция `014_stopper_manager.sql` добавляет роль и должность `manager`; у должности выключен выбор магазина),
с проверкой CSRF.

- `GET /stoppers/` — справочник; `positions` — число позиций со стоппером.
- `POST /stoppers/`, `PUT /stoppers/{id}` — JSON `{"name":"Сезон","color":"#1F5FBF"}`.
  Занятое имя — 409.
- `DELETE /stoppers/{id}` — позиции остаются без стоппера.
- `GET /stoppers/positions?from=2026-11-05&to=2026-11-19&store_id=…` — позиции,
  чей период пересекается с окном; `store_id` можно передать до 4 раз — для цен.
- `POST /stoppers/positions` — ручная позиция:
  `{"product_id":"…","stopper_id":3,"from":"2026-11-12"}`. Уже есть — 409.
- `PUT /stoppers/positions/stopper` — `{"positions":[{"doc_id":"…","product_id":"…"}],"stopper_id":3}`;
  `stopper_id: null` снимает стоппер. До 500 позиций, всё или ничего.
- `PUT /stoppers/positions/period` — `{"positions":[…],"from":"2026-11-15","to":"2026-11-30"}`;
  `to: null` — без срока.
- `GET /stoppers/products?q=…` — поиск товара по коду или названию для ручного
  добавления (до 30); `added` — у товара уже есть ручная позиция.

Пример позиции:

```json
{"doc_id":"…","product_id":"…","code":"ЦБ-00002966","name":"Товар","thermal_mode":true,"stopper_id":3,"from":"2026-11-15","to":"2026-11-30","received":"2024-01-10","manual":false,"stores":154,"prices":[{"store_id":"…","price":"1490.00","promo_price":"1190.00"}]}
```

`received` — дата появления акции в 1С (для ручной позиции — дата добавления).

## Задание магазину «Стопперы»

Миграция `013_stopper_tasks.sql` добавляет сервис `stoppers` в `task_types`, тип задания
«Стопперы», колонку `tasks.manual` и таблицу `stopper_task_checks`.

Задание создаётся по расписанию, как остальные, или вручную кнопкой «+» на главной:
`POST /tasks/manual` (любой вошедший, JSON `{"type_id":1,"store_id":"…"}`) создаёт задание
активного типа для магазина со временем начала «сейчас» (часовой пояс `scheduler.timezone`).
У магазина может быть только одно открытое («Новое» или «Выполняется») задание «Стопперы»:
второе вручную не создаётся (409), а по расписанию не добавляется. Незавершённое задание не пропадает
в полночь — `GET /tasks/current` показывает его и на следующие дни, пока его не завершат или не отменят
(отметки сохраняются). «Печать ценников» тоже висит, пока не напечатано всё, но его RMS ведёт сам
(см. `docs/price_tags.md`); остальные типы заданий — только за сегодня.
Задание «Стопперы» не создаётся и тогда, когда оно было бы пустым: у магазина на сегодня нет
ни действующего стоппера для проверки, ни закончившегося за 14 дней для снятия. Вручную — 409,
по расписанию задание для такого магазина не добавляется (а ещё не начатое удаляется при сверке).
У ручных заданий `manual = true`, ежечасная сверка с расписанием (`task_generation`) их не удаляет.
`GET /tasks/types?store_id=…` — активные типы заданий для этой кнопки; `available: false` у
«Стопперов», если для магазина задание было бы пустым (без `store_id` все типы доступны).

`GET /tasks/{id}/stoppers` — экран задания: позиции со стоппером, которые действуют сегодня
в магазине задания (документ акции 1С по акционному типу цен магазина или ручная позиция),
и позиции, чей период закончился за последние 14 дней (`remove: true`), — их нужно снять,
если у товара нет другого действующего стоппера. У позиции: остаток, единица (`кг` для весовых),
обычная и акционная цена магазина, штрих-код, стоппер и отметка `result`.

`PUT /tasks/{id}/stoppers/check` — отметка магазина `{"doc_id":"…","product_id":"…","result":"ok"}`:
`ok` — соответствует, `bad` — не соответствует (ценник в печать), `removed` — стоппер снят,
пустая строка снимает отметку. Первая отметка переводит задание в работу; отметки закрытого
задания менять нельзя. Завершается задание обычным `POST /tasks/{id}/complete`.
